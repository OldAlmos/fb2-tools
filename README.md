# fb2-tools

[![tests](https://github.com/OldAlmos/fb2-tools/actions/workflows/tests.yml/badge.svg)](https://github.com/OldAlmos/fb2-tools/actions/workflows/tests.yml)

Инструмент командной строки для больших коллекций книг в формате FB2 (FictionBook 2): находит повреждённые файлы, автоматически чинит типичные поломки заголовка и выдаёт отчёты в CSV и JSON. Работает на Linux и Windows, внешних зависимостей нет.

## Зачем это нужно

Программы для редактирования метаданных и конвертеры иногда записывают заголовок FB2 с неправильной длиной. В результате файл перестаёт открываться в читалках. Типичные случаи:

- обрезанный корневой тег:

  ```xml
  <FictionBook xmlns="http://www.gribuser.ru/xml/fictionbook/2.0" xmlns:l="http://www.w3.org/1999/x<description>
  ```

- «хвост» от старого содержимого после закрывающего тега:

  ```xml
  </description>on>on>on>
  ```

Текст самой книги при этом обычно цел, поэтому такие файлы можно исправить автоматически.

## Требования

Python 3.12 или новее. Сторонние пакеты для работы не нужны.

## Установка

### Linux (Ubuntu)

Вариант 1: отдельная команда `fb2tools` через `pipx` (удобно для повседневного использования):

```bash
sudo apt install pipx
pipx ensurepath
pipx install git+https://github.com/OldAlmos/fb2-tools.git
```

Обновление: `pipx upgrade fb2-tools`.

Вариант 2: из клона репозитория, в виртуальном окружении:

```bash
git clone https://github.com/OldAlmos/fb2-tools.git
cd fb2-tools
python3 -m venv .venv
.venv/bin/pip install -e .
```

Команда будет доступна как `.venv/bin/fb2tools`.

### Windows

```powershell
git clone https://github.com/OldAlmos/fb2-tools.git
cd fb2-tools
py -3.12 -m venv .venv
.venv\Scripts\pip install -e .
```

Команда: `.venv\Scripts\fb2tools` (или `fb2tools`, если окружение активировано).

## Использование

```bash
# 1. Найти файлы с ошибками (файлы не меняются)
fb2tools check /путь/к/библиотеке

# 2. Посмотреть, что будет исправлено (файлы не меняются)
fb2tools fix /путь/к/библиотеке

# 3. Исправить; оригиналы сохраняются как *.fb2.bak
fb2tools fix /путь/к/библиотеке --fix

# 4. Перепроверить
fb2tools check /путь/к/библиотеке

# 5. Удалить резервные копии (спросит подтверждение; --yes без вопроса)
fb2tools clean /путь/к/библиотеке
```

Эквивалентная форма запуска: `python -m fb2tools check ПАПКА`.

Коды возврата: `0` всё в порядке; `1` `check` нашёл ошибки или `clean` не смог удалить файл; `2` ошибка запуска (папки нет, отчёт не удалось записать). Это удобно для скриптов и cron.

### Отчёты в CSV и JSON

```bash
fb2tools check /путь/к/библиотеке --format csv  --output report.csv
fb2tools check /путь/к/библиотеке --format json --output report.json
fb2tools check /путь/к/библиотеке --format csv --all --output full.csv   # и файлы без ошибок
```

Для csv и json рекомендуется `--output`: файл пишется в UTF-8 (CSV с BOM, чтобы Excel правильно показал кириллицу). Без `--output` отчёт выводится в консоль, а итоговая строка `Проверено: N, с ошибками: M` всегда идёт в stderr и в отчёт не попадает.

**CSV**: одна строка на одну проблему. Столбцы:

| Столбец | Значение |
|---------|----------|
| `path` | путь к файлу |
| `status` | `error` или `ok` (только с `--all`) |
| `code` | устойчивый код проблемы (см. ниже) |
| `message` | описание проблемы |
| `fixable` | `yes`, если `fix --fix` полностью исправит файл, иначе `no` |

**JSON**: объект с полями `generated`, `tool_version`, `folder`, `total`, `with_errors` и списком `files`. У каждого файла есть `path`, `ok`, `fixable` и список `problems` из пар `code` и `message`.

**Коды проблем:**

| Код | Что означает |
|-----|--------------|
| `xml_parse` | XML не разбирается |
| `wrong_root` | корневой элемент не `FictionBook` FB2 |
| `stray_text` | посторонний текст внутри `<FictionBook>` |
| `no_description`, `no_title_info`, `no_book_title` | нет обязательной части заголовка |
| `no_body` | нет `<body>` |
| `missing_binary` | ссылка на картинку без соответствующего `<binary>` |
| `zip_no_fb2` | в архиве нет `.fb2` |
| `read_error` | файл не удалось прочитать |

### Что проверяет `check`

Корректность XML, корневой элемент, посторонний текст между элементами, наличие `<description>`, `<title-info>`, `<book-title>` и `<body>`, ссылки на изображения без `<binary>`. Поддерживаются файлы `.fb2` и `.fb2.zip`. Это не полная валидация по XSD: проверяется только то, что важно для открытия книги. Строгая проверка по схеме слишком придирчива, многие рабочие книги её не проходят.

### Что чинит `fix`

- обрезанный корневой тег `<FictionBook ...`;
- мусор сразу после `</description>`.

Файлы `.fb2.zip` пока только проверяются, но не чинятся.

### Безопасность

- `fb2tools fix` без `--fix` ничего не записывает.
- Перед записью исправленный файл проверяется на корректность XML. Если после правки он всё ещё не разбирается, файл остаётся нетронутым и помечается в выводе.
- Перед каждой правкой рядом сохраняется копия `имя.fb2.bak`; `fb2tools clean` удаляет только файлы `*.fb2.bak`.
- Работа идёт с байтами, поэтому кодировка файла (UTF-8, windows-1251) значения не имеет.

Перед массовым исправлением на ценной коллекции всё равно сделайте полную резервную копию.

## Структура проекта

```
fb2tools/
├── checker.py   # проверка структуры FB2, коды проблем
├── fixer.py     # починка известных повреждений
├── cleaner.py   # удаление резервных копий *.fb2.bak
├── report.py    # отчёты в форматах text, csv, json
└── cli.py       # командная строка (check, fix, clean)
tests/           # тесты pytest
check_fb2.py     # обёртка для совместимости: fb2tools check
fix_fb2.py       # обёртка для совместимости: fb2tools fix
```

Логика вынесена в функции, которые возвращают результат, а не печатают его (`diagnose_file`, `scan`, `process_file`), поэтому их можно использовать из других программ, например из веб-интерфейса.

## Разработка

```bash
pip install -e ".[dev]"
pytest
```

Тесты автоматически запускаются на GitHub Actions на Ubuntu и Windows при каждом коммите в `main`. Новое правило починки добавляется вместе с тестом на заведомо битый файл.
